# How to submit an issue for GEM

If you already know that the issue is related to one of GEM or SPS
components, please open an issue directly in its repo:

[modelutils](https://gitlab.science.gc.ca/MIG/modelutils/issues)

[rpnphy](https://gitlab.science.gc.ca/MIG/rpnphy/issues)

[gemdyn](https://gitlab.science.gc.ca/dynamics_research/gemdyn/issues)

[mach](https://gitlab.science.gc.ca/ARQI-GEMMACH/GEM-MACH/issues)

[spsdyn](https://gitlab.science.gc.ca/continental-surface-hydrology/sps-dev/issues)

[gem-maestro](https://gitlab.science.gc.ca/MIG/gem-maestro)

If you are not sure your issue is related to a specific component, or if it
is related to a general problem in GEM (compilation process, content or use
of GEM repo, problem with an installed version of GEM, etc.), open an issue
in [GEM](https://gitlab.science.gc.ca/MIG/gem/issues).

Do not submit an issue in
[MIG/mig](https://gitlab.science.gc.ca/MIG/mig/issues), only old issues
submitted before the migration to the new cmake system are there.
